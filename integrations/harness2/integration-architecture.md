# Implemented boundaries

The launcher imports the unchanged pinned upstream and enters `bridge.integrated`. Three trusted runtime hooks wrap existing seams: `_run_stage` supplies authenticated stage/base/library context, `_accept_tree` retains original checks then invokes the authority, and the existing benchmark adapter delegates execution through receipt verification. A guarded subclass of the original Library checks adopted-run receipts and produces clean snapshots for subsequent context construction. Hooks are process-local and restored on exit; one dedicated launcher owns their lifetime. No upstream source is patched.

A complete c1–c8 file tree is one versioned `harness` component, depending on immutable guardrail/policy/verifier metadata. Several files are materialized and published as one immutable bundle. This maps an existing supported core update to a whole artifact bundle; it does not add multi-target metadata transactions or claim independent field-level proofs. Actual file references/schema and the execution catalog are required trusted validators.

Parallel candidates remain independent branches. The authority uses checked historical recovery to the actual branch base before preparing a new unique version. Known branch lineage and registered library-exposure origins remain bound to receipts. The current monotone withdrawal set survives switching. A withdrawn version or known derivative cannot execute, recover or enter future library context. Existing histories stay available for auditing rather than being silently deleted.

Preparation binds canonical DSL, principal, policy, verifier source, candidate bytes, base, evidence and version origins. Commit verifies the pending approval under the authority lock. Complete files are staged privately, renamed as one directory and exposed as executable only after a separate publication receipt. Filesystem existence alone grants no authority. A failure before that receipt cannot execute; a failed trace after metadata advancement triggers checked compensation. Reopening a nonempty store is refused because durable recovery is not implemented.

Before each real executor call the mutable upstream stage directory must match its registered task/stage receipt. Execution uses a fresh copy of attested catalog bytes and holds the authority lock until the subprocess/model rollout returns. Consequently policy withdrawal cannot race an active lease. The bounded model backend exposes only a fixed summary-tool action and final text, with no arbitrary shell/host access. Available/reached/carried records describe actual model actions and downstream use; the deterministic backend's known tool path is recorded separately.

This trust model excludes hostile arbitrary tool-enabled agents sharing the authority's OS permissions. A separate directory or hash list alone would not isolate those agents; such executors are explicitly unsupported until an OS boundary and additional validators are implemented and tested.
