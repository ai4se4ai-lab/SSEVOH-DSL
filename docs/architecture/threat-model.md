# Trust boundary

The adversary controls proposal text, model responses, and claimed evidence. It can replay proposals, race deployments, request privilege expansion, change dependencies, and request recovery of a withdrawn version. It cannot modify operator policy, trusted validator registration, the enforcement process, its memory, audit storage, or the OS isolation boundary.

The sandbox prevents text from executing code; policy is not parsed from model text. Evidence is generated by registered host validators and bound to proposal and current state fingerprints. Approval capabilities are private engine records, single-use, and checked again under the deployment lock. A stale approval is rejected after any state change. This conservative invalidation includes unrelated changes.

Out of scope: compromised Python interpreter or host, malicious operator validators, deployment to production, external side effects, distributed transactions, prompt usefulness, and persistent crash recovery. Hash chaining detects accidental audit changes only relative to a retained trusted head; it is not an external signature or append-only storage guarantee.
