# Changes to the upstream use-hpc template

Upstream revision: `UPSTREAM_COMMIT`. The orchestration, contracts, ledger, audit, requeue and collector remain upstream components.

Project changes: configured graph/site environment; Ollama service hook; fleet/SSH/measurement/publication tools; CPU-only scheduled formal/analysis stages to avoid idle GPU requests. `submit.py` additionally freezes the source under each run's persistent log directory. Its submitted stage script, common helpers, hooks and runner execute that snapshot. `hpclib.py` resolves REPO from FROZEN_REPO_DIR. Stage configuration remains frozen by upstream as before. Original initial exploratory smoke submissions predate this source-freeze extension and must be identified accordingly.

This source freeze isolates later repairs/deployments from running experiments. It uses a filesystem snapshot by copying source; no privileged filesystem snapshot or immutable storage claim is made.

Harness² qualification snapshots are preserved separately from full-study snapshots. Before full submission, the worker metrics reader was corrected to use the upstream seeded namespace (`-s1701`, etc.). Initial smoke task-success summaries are excluded from effectiveness analysis; raw answers and traces are retained. Qualification's GPU residency, completion/accounting, resume and transfer measurements do not depend on the task-success reader. The full deployment also records requests before transport and archives unfinished attempts instead of deleting them. These observer/recovery changes do not change the checked core or adapter semantics. Exact source identities remain in each run snapshot.

The primary DSL generator's independent oracle now uses the separately implemented operational reference over trusted state, history and version origins. It does not invoke runtime candidate, policy checking or validators to decide labels; fixture evidence availability is specified independently. The old exploratory oracle omitted protected dependent kinds and historical-origin checks and must not support current enforcement findings.

The Harness² pooled analyzer reports authority-only lifecycle rows in separate `:lifecycle` groups, so C0–C3 shared-fixture denominators stay comparable. Initial per-site summaries that combined those groups are intermediate and superseded by the scheduled pooled analysis. Raw records include schema/scenario identities and are unchanged; no inference is repeated for this derived-table correction. The aggregate snapshots the verified current analysis tools before computation.

Additional project workers provide synthetic mechanism-removal ablations, pre-generation GPU residency checks with identical node-local runtime libraries, and scheduled pooled cross-site statistics. Full source snapshots include a regression guard preventing historical recovery from exceeding the current capability ceiling; runtime qualification data retains its own original source/config identities.

Coding-study repairs: provenance hashing reads the per-run frozen source rather than the live hpc tree, whose prior logs/results otherwise dominate submission latency and contaminate code identities. Source-hash independence has regressions. The inference hook enumerates pinned node-local CUDA backends offline before Ollama startup to warm cold driver/library paths; it never loads a model or evaluates a task. Full-GPU residency remains mandatory. Run-scoped collection can omit redundant source copies while retaining the full source-snapshot manifest; raw results and logs remain transfer-hash verified. The coding coordinator uses an exclusive lock, immutable release fingerprints, persistent whole-stream submission intents, exact global population freezing and a separate CPU evaluation graph. It does not replace native Slurm scheduling.
